# Lab 04 — K3s

**Goal:** See how Kubernetes keeps the app alive.

## Idea

Kubernetes receives a declared state ("2 replicas of this image") and keeps it: if a pod dies, it creates another one. K3s is full Kubernetes in a lightweight binary, with Ingress (Traefik) and storage (`local-path`) included. It is installed by script, before everything else.

## How it works

| Object | In SmartLink |
| --- | --- |
| Namespace | One per component: `smartlink-backend`, `smartlink-frontend`, `vault`, `vault-secrets-operator`, `loki`, `alloy`, `grafana`, `argocd`, `traefik` (one per folder in `deploy/components/`) |
| Deployment | `smartlink-api` (2 replicas), `smartlink-frontend` (1) |
| Service | Stable DNS name to the healthy pods |
| Ingress | `/` → API, `/app` → dashboard |
| PVC | Vault and Loki disks |

## Do it

Run the commands in the VM (`./scripts/install.sh shell`) or, from your Mac, prefix them: `./scripts/install.sh k get pods -A`. More in [Run commands on the cluster](../install.md#4-run-commands-on-the-cluster).

Diagnosis in three steps:

```bash
k get pods -A                                                    # 1. state
k -n smartlink-backend describe pod <pod> | sed -n '/Events/,$p' # 2. what happened to it
k -n smartlink-backend logs deploy/smartlink-api --tail=20       # 3. what the app said
```

Kill the pods with traffic running in another terminal:

```bash
while true; do curl -s -o /dev/null -w "%{http_code}\n" http://<vm-ip>/health; sleep .5; done
k -n smartlink-backend delete pod -l app.kubernetes.io/name=smartlink-api
```

The Deployment recreates them, and the `200`s keep coming (or stop for a few seconds).

## Break it

[💥 ImagePullBackOff](../break.md#1-imagepullbackoff) · [💥 CrashLoopBackOff](../break.md#2-crashloopbackoff)

## Key points

- Kubernetes is a loop: it compares what was declared with what is real, and corrects it.
- A pod that does not start → events. A pod that dies → `logs --previous`.
