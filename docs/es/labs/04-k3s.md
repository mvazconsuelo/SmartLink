# Lab 04 — K3s

**Objetivo:** Ver cómo Kubernetes mantiene la app viva.

## Idea

Kubernetes recibe un estado declarado ("2 réplicas de esta imagen") y lo sostiene: si un pod muere, crea otro. K3s es Kubernetes completo en un binario liviano, con Ingress (Traefik) y discos (`local-path`) incluidos. Se instala a mano, antes que todo lo demás.

## Cómo funciona

| Objeto | En SmartLink |
| --- | --- |
| Namespace | Uno por componente: `smartlink-backend`, `smartlink-frontend`, `vault`, `vault-secrets-operator`, `loki`, `alloy`, `grafana`, `argocd`, `traefik` (uno por carpeta de `deploy/components/`) |
| Deployment | `smartlink-api` (2 réplicas), `smartlink-frontend` (1) |
| Service | Nombre DNS estable hacia los pods sanos |
| Ingress | `/` → API, `/app` → dashboard |
| PVC | Discos de Vault y Loki |

## Hacelo

Corré los comandos en la VM (`./scripts/install.sh shell`) o, desde tu Mac, con el prefijo: `./scripts/install.sh k get pods -A`. Más en [Correr comandos en el cluster](../install.md#4-correr-comandos-en-el-cluster).

Diagnóstico en tres pasos:

```bash
k get pods -A                                                    # 1. estado
k -n smartlink-backend describe pod <pod> | sed -n '/Events/,$p' # 2. qué le pasó
k -n smartlink-backend logs deploy/smartlink-api --tail=20       # 3. qué dijo la app
```

Matá los pods con tráfico en otra terminal:

```bash
while true; do curl -s -o /dev/null -w "%{http_code}\n" http://<ip-vm>/health; sleep .5; done
k -n smartlink-backend delete pod -l app.kubernetes.io/name=smartlink-api
```

El Deployment los recrea, y los `200` siguen (o se cortan segundos).
