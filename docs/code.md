# 🧩 The code

**A map of the application code.** It is small on purpose: the lab is about the platform around it. Everything here is real and checked against the source.

Convention: every public function and class has a one-line docstring that says **what** it does; the comments say **why**.

## Where things are

```text
backend/
├── app/            the API (FastAPI)
├── tests/          its tests
├── Dockerfile · requirements.txt · requirements-dev.txt
frontend/
├── app.py          the dashboard (Streamlit), a single file
└── Dockerfile · requirements.txt
migrations/         the D1 schema, one numbered SQL file per change
scripts/            the installer (see Lab 05)
deploy/             what Argo CD deploys (see Lab 06)
.github/workflows/  ci.yaml (see Lab 08)
```

## The backend

A request goes down three layers. Only the last one talks to D1.

```text
HTTP        main.py         routes, status codes, logging
  │
Logic       auth.py  shortener.py  analytics.py  qr.py
  │
Data        database.py     the only code that runs SQL against D1
```

| Module | Responsibility |
| --- | --- |
| `main.py` | `create_app()` builds the API: routes, the request log, and how errors become HTTP answers |
| `auth.py` | Passwords (PBKDF2) and tokens (JWT). `get_current_user` is the dependency that protects a route |
| `shortener.py` | Creating and resolving links: codes, aliases, reserved words, expiration |
| `analytics.py` | Recording a click, and the numbers behind the dashboard |
| `database.py` | The `Database` interface and `D1Database`, which talks to D1's REST API |
| `config.py` | Reads the environment. A missing or insecure value stops the app at startup |
| `schemas.py` | The request and response models |
| `qr.py` | Draws a QR code. Nothing is stored |

Rules the code follows, and why:

- **Only `database.py` runs SQL against D1.** The rest depends on the `Database` interface, so the tests swap D1 for an in-memory fake.
- **A failure of D1 is not a bug.** D1 unreachable → `DatabaseUnavailable` → `503`. D1 rejects the SQL → `QueryError` → `500`.
- **Recording a click can fail without breaking the redirect.** The visitor still gets where they were going; the lost click is logged.
- **`/health` does not check D1.** Restarting pods would not fix an outside dependency.
- **The redirect is `302`**, never `301`: a browser caches a `301` and later clicks would not arrive.
- **`/{code}` is registered last**, because it matches any single path segment.

## The API

| Method and path | Needs a token | Answers |
| --- | --- | --- |
| `GET /health` | No | `200` `{"status": "ok"}` |
| `POST /auth/register` | No | `201` a token · `409` the username exists · `403` registration is disabled |
| `POST /auth/login` | No | `200` a token · `401` wrong credentials |
| `POST /shorten` | Yes | `201` the link · `409` alias in use · `422` invalid alias, URL or expiration |
| `GET /urls` | Yes | `200` your links |
| `GET /urls/{code}` | Yes | `200` the link with its statistics · `404` it does not exist or is not yours |
| `GET /urls/{code}/qr` | Yes | `200` a PNG |
| `GET /stats` | Yes | `200` your totals, clicks per day, top links and latest clicks |
| `GET /{code}` | No | `302` to the target · `404` unknown · `410` expired |

Any route can also answer `401` (no or invalid token), `503` (D1 unreachable) or `500`. The interactive version, with every field, is `http://<ip>/docs`.

## Configuration

Read once at startup by `config.py`. In the cluster they all arrive from the `smartlink-backend` Secret, which VSO builds from Vault ([Lab 07](labs/07-vault.md)).

| Variable | Required | Default | Notes |
| --- | --- | --- | --- |
| `JWT_SECRET` | Yes | | At least 32 characters; generated by the installer |
| `PUBLIC_BASE_URL` | Yes | | The base of the short links and QR codes |
| `D1_ACCOUNT_ID`, `D1_DATABASE_ID`, `D1_API_TOKEN` | Yes | | How to reach D1 |
| `D1_TIMEOUT_SECONDS` | No | `5` | |
| `JWT_TTL_MINUTES` | No | `60` | How long a token lives |
| `ALLOW_REGISTRATION` | No | `true` | `false` closes sign-ups |
| `LOG_LEVEL` | No | `INFO` | |

The dashboard has one: `API_URL`, the address of the API (in the cluster, the backend's Service).

## The data

Three tables, created by the migrations in `migrations/` ([Lab 02](labs/02-d1.md)). Timestamps are UTC text, `YYYY-MM-DD HH:MM:SS`.

| Table | Columns |
| --- | --- |
| `users` | `id`, `username` (unique), `password_hash`, `created_at` |
| `short_urls` | `id`, `user_id`, `code` (unique), `original_url`, `created_at`, `expires_at` (migration 002), `is_active`, `click_count` |
| `click_events` | `id`, `short_url_id`, `clicked_at`, `referrer` (the site only), `user_agent` (cut to 200 characters) |

`is_active` is read by the status (`active`, `expired`, `inactive`), but nothing in the API sets it to `0` yet.

## The logs

One line per event, `key=value`, to stdout: `level=INFO logger=smartlink.api msg=…`. The ones the labs use:

| Message | When |
| --- | --- |
| `request method=… path=… status=… duration_ms=…` | Every request (`/health` only at debug level, unless it fails) |
| `redirect not_found code=…` · `redirect expired code=…` | A redirect that did not happen |
| `click not recorded code=…` | The redirect worked, the analytics did not |
| `d1 request failed reason=auth\|timeout\|connection\|upstream\|invalid_json` | D1 could not be reached ([failure 4](break.md#4-d1-failure)). The token is never logged |
| `d1 query rejected … error=…` | D1 refused the SQL |

How to query them: [Lab 11](labs/11-observability.md).

## The dashboard

`frontend/app.py` is one file. `api()` is the only place that makes HTTP calls: it adds the token, turns errors into `ApiError`, and sends you back to the login when the token expires. The token lives in the browser session (`st.session_state`). It never talks to D1.

## The tests

33 tests, with no network and no Cloudflare. `FakeD1` is an in-memory SQLite that loads the real files in `migrations/`, so the tests run the application's real SQL on the real schema. `BrokenD1` simulates an outage.

| File | What it checks |
| --- | --- |
| `test_api.py` | The API end to end: accounts, links, aliases, expiration, redirects, ownership, QR, dashboard, `503` and `500` |
| `test_d1_client.py` | `D1Database` against a fake HTTP transport: what it sends, timeouts, errors, and that the token is never logged |

To run them and the checks CI runs:

```bash
cd backend && pip install -r requirements-dev.txt && pytest -q
cd .. && ruff check backend frontend && ruff format --check backend frontend
```

## Changing it

- **A new endpoint.** Put the logic in `shortener.py` or `analytics.py`, the models in `schemas.py`, and the route in `main.py` **above** `/{code}`. Its docstring becomes its text in `/docs`. Add a test in `test_api.py`.
- **A new column or table.** A new numbered file in `migrations/`, always additive ([Lab 02](labs/02-d1.md)).
- **A new setting.** Read it in `config.py`; to give it a value in the cluster, add it to the Secret's values in Vault (`./scripts/install.sh secrets`, or `v kv patch secret/smartlink/backend NAME=value`).
